什么是 Gleam 入门

Gleam 是一门类型安全的函数式编程语言，可编译到两个目标：

  • Erlang (BEAM VM) — 继承 Erlang/Elixir 的并发性、容错能力和热代码重载
  • JavaScript — 可运行于 Node.js、Deno、Bun 及主流浏览器

核心设计哲学

  • 函数式：不可变数据，函数是一等公民
  • 静态类型：编译期类型检查，类型推断（大多数时候无需手写类型标注）
  • 没有 null、没有异常：用 Result 类型处理错误，用 Option 类型表示可能缺失的值
  • 没有隐式转换、没有循环、没有宏、没有类型类（type classes）
  • 流控制依赖模式匹配（case）和递归
  • 语法风格类似 Python/Rust，清晰易读

import gleam/io

pub fn main() {
  io.println("Hello, Joe!")
}

ML 对比

Gleam 语法是 C/Python 风格大括号，不是 ML 的 let ... in ...。Gleam 没有类型类，没有异常，没有高阶类型（HKT）。

💡 提示

如果你有 OCaml/Haskell 经验，Gleam 的类型系统是"ML 减去类型类和高阶类型"。语法上更接近 Rust。

类型系统 入门

Gleam 的类型系统是语言的核心优势。本节介绍自定义类型、类型别名、记录和泛型。

自定义类型（Custom Types）

自定义类型即 ML 的 variant/sum type，是 Gleam 类型系统的核心。

gleam
pub type Shape {
  Circle(radius: Float)
  Rectangle(width: Float, height: Float)
  Triangle(base: Float, height: Float)
}

pub fn area(shape: Shape) -> Float {
  case shape {
    Circle(r) -> 3.14159 *. r *. r
    Rectangle(w, h) -> w *. h
    Triangle(b, h) -> 0.5 *. b *. h
  }
}

编译器确保所有 case 分支都被处理。漏掉一个 → 编译错误。

模式匹配 入门

模式匹配是 Gleam 的核心控制流机制，替代了 if-else、switch 和解构赋值。

基本模式匹配

gleam
case some_value {
  Ok(value) -> "Success: " <> value
  Error(_) -> "Failed"
}

列表模式匹配

gleam
case list {
  [] -> "empty"
  [first] -> "one: " <> first
  [first, second] -> "two: " <> first <> ", " <> second
  [first, ..rest] -> "many: " <> first
}

带守卫的模式匹配

gleam
case n {
  _ if n > 0 -> "positive"
  _ if n < 0 -> "negative"
  _ -> "zero"
}
ML 对比

Gleam 的模式匹配与 OCaml 的 match ... with 几乎完全一致，包括守卫语法。编译器强制穷尽性检查。

管道运算符与 use 表达式 入门

管道运算符 |>

管道运算符将左边的值作为右边函数的最后一个参数传入。

gleam
"hello"
|> string.uppercase
|> string.reverse
// 等价于 string.reverse(string.uppercase("hello"))

use 表达式

use 是 Gleam 的语法糖，用于回调风格的 API，类似 Haskell 的 do notation。

gleam
use result <- result.try(get_user(id))
use profile <- result.try(get_profile(result.id))
Ok(profile)

展开后等价于：

gleam
result.try(get_user(id), fn(result) {
  result.try(get_profile(result.id), fn(profile) {
    Ok(profile)
  })
})
💡 提示

use 表达式让回调代码读起来像顺序代码，在 Wisp 中大量使用。

Result 与 Option 入门

Gleam 没有 null 和异常，用 Result 和 Option 类型处理错误和缺失值。

Result 类型

gleam
pub type Result(a, e) {
  Ok(a)
  Error(e)
}

链式错误处理

gleam
import gleam/result

pub fn safe_divide(a: Int, b: Int) -> Result(Int, String) {
  case b {
    0 -> Error("division by zero")
    _ -> Ok(a / b)
  }
}

pub fn compute() -> Result(Int, String) {
  use x <- result.try(safe_divide(10, 2))
  use y <- result.try(safe_divide(x, 3))
  Ok(y)
}
ML 对比

Gleam 的 Result 类似 Haskell 的 Either。result.try 对应 monadic bind（>>=）。

Wisp 框架概览 入门

Wisp 是 Gleam 的 Web 框架，提供路由、请求/响应处理、中间件等 Web 应用常用功能。它建立在 Mist HTTP 服务器之上。

最小 Wisp 应用

gleam
import wisp
import wisp/wisp_mist
import mist

pub fn main() {
  let secret = wisp.random_string(64)
  let assert Ok(_) =
    handle_request
    |> wisp_mist.handler(secret)
    |> mist.new
    |> mist.bind("localhost")
    |> mist.port(8000)
    |> mist.start
}

fn handle_request(req: wisp.Request) -> wisp.Response {
  wisp.html_response("<h1>Hello, Wisp!</h1>", 200)
}

架构层次

应用代码 → Wisp（Web 框架）→ wisp_mist（适配层）→ Mist（HTTP 服务器）→ BEAM VM
💡 提示

Wisp 的设计类似 Phoenix (Elixir) 或 Sinatra (Ruby)，简洁的路由 + 强大的中间件系统。

路由定义 入门

Wisp 使用模式匹配定义路由，通过 wisp.path_segments 获取路径段进行匹配。

基本路由

gleam
fn handle_request(req: wisp.Request) -> wisp.Response {
  case wisp.path_segments(req) {
    [] -> home_page(req)
    ["users"] -> list_users(req)
    ["users", id] -> get_user(req, id)
    ["posts", "new"] -> new_post(req)
    _ -> wisp.not_found()
  }
}

HTTP 方法路由

gleam
case wisp.method(req), wisp.path_segments(req) {
  wisp.Get, [] -> index_page(req)
  wisp.Post, ["users"] -> create_user(req)
  wisp.Get, ["users", id] -> show_user(req, id)
  wisp.Put, ["users", id] -> update_user(req, id)
  wisp.Delete, ["users", id] -> delete_user(req, id)
  _, _ -> wisp.not_found()
}
💡 提示

路由本质就是 case 表达式匹配，Gleam 的模式匹配让路由定义既灵活又类型安全。

中间件 进阶

中间件是 Wisp 的核心设计，用 use 表达式组合。中间件按洋葱模型执行：请求从外到内，响应从内到外。

常用中间件

gleam
fn handle_request(req: wisp.Request) -> wisp.Response {
  use <- wisp.rescue_crashes
  use <- wisp.log_request(req)
  use <- wisp.serve_static(req, under: "/static", from: "priv/static")

  // 路由处理
  case wisp.path_segments(req) {
    [] -> wisp.html_response("Hello", 200)
    _ -> wisp.not_found()
  }
}

中间件执行顺序（洋葱模型）

请求 → rescue_crashes → log_request → serve_static → handler 响应 ← rescue_crashes ← log_request ← serve_static ← handler
ML 对比

中间件本质是高阶函数组合，ML 程序员应很熟悉。类似 OCaml 的 functors 或 Haskell 的 monad transformers。

Wisp Body 类型

Wisp 的 Body 类型有三种形式，其中 File 支持零拷贝发送：

形式说明
Text字符串内容
Bytes二进制数据
File文件路径（零拷贝 sendfile）

文件上传（multipart）

gleam
fn handle_upload(req: wisp.Request) -> wisp.Response {
  use <- wisp.require_multipart_body(req, max_body_size: 10_000_000)
  let form = wisp.multipart_body(req)

  // form.values — 普通字段
  // form.files — 上传文件
  let filename = form |> wisp.get_form_field("filename")

  case wisp.get_form_file(form, "upload") {
    Ok(file) -> {
      // file.filename — 原始文件名
      // file.content_type — MIME 类型
      // file.data — 文件内容
      save_file(file)
      wisp.redirect(to: "/success")
    }
    Error(_) -> wisp.bad_request()
  }
}
ML 对比

零拷贝文件发送类似 OCaml 的 sendfile 系统调用封装，避免将文件内容读入内存。

Mist 概览 进阶 新增

Mist 是 Gleam 的底层 HTTP 服务器库。Wisp 建立在 Mist 之上：Wisp = Web 框架，Mist = HTTP 服务器。

核心类型

类型说明

WebSocket 完整示例

gleam
import mist
import gleam/io

pub fn main() {
  let assert Ok(_) =
    handle_request
    |> mist.new
    |> mist.port(4000)
    |> mist.start
}

fn handle_request(req: mist.Request) -> mist.Response {
  case mist.get_header(req, "upgrade") {
    Ok("websocket") -> {
      mist.websocket(
        req,
        on_init: fn() { Nil },
        on_close: fn(_state) { io.println("Closed") },
        handler: handle_ws,
      )
    }
    _ -> mist.new_response(200) |> mist.set_body("Not a WebSocket")
  }
}

fn handle_ws(state: Nil, message: mist.WebSocketMessage(Nil), conn: mist.WebSocketConnection) {
  case message {
    mist.Text(msg) -> {
      let assert Ok(_) = mist.send_text_frame(conn, "Echo: " <> msg)
      mist.continue(state)
    }
    mist.Binary(data) -> {
      let assert Ok(_) = mist.send_binary_frame(conn, data)
      mist.continue(state)
    }
    mist.Closed -> {
      io.println("Connection closed")
      mist.stop()
    }
    _ -> mist.continue(state)
  }
}

  Tick
  StartLoading

  #(Model(count: 0, loading: False), effect.none())
}

fn update(model: Model, msg: Message) -> #(Model, effect.Effect(Message)) {
  case msg {
    StartLoading -> #(Model(..model, loading: True), load_data())
    Tick -> #(Model(..model, count: model.count + 1, loading: False), effect.none())

}

    // 异步操作完成后调用 dispatch
    dispatch(Tick)
  })
}

  case msg {
    FetchUsers -> #(
      Model(..model, users: Loading),
      rsvp.get("/api/users")
      |> rsvp.expect_json(user_list_decoder(), UsersLoaded)
      |> rsvp.to_effect,
    )
    CreateUser(name) -> #(
      model,
      rsvp.post("/api/users")
      |> rsvp.with_body(json.to_string(json.object([#("name", json.string(name))])))
      |> rsvp.expect_json(user_decoder(), UserCreated)
      |> rsvp.to_effect,
    )
    UsersLoaded(Ok(users)) -> #(
      Model(..model, users: Loaded(users)),
      effect.none(),
    )
    UserCreated(Ok(user)) -> #(
      Model(..model, users: case model.users {
        Loaded(list) -> Loaded([user, ..list])
        _ -> Loaded([user])
      }),
      effect.none(),
    )
    _ -> #(model, effect.none())
  }
}

常见问题 FAQ

Gleam 有类型类吗？

没有。Gleam 刻意不实现类型类（type classes），以保持类型系统简单。如果你需要类似功能，可以用 Gleam 的模块系统手动传递实现。

Gleam 有异常吗？

没有。Gleam 完全用 Result(a, e) 类型替代异常。错误处理通过模式匹配和 result.try 完成。

Gleam 支持高阶类型（HKT）吗？

不支持。Gleam 的类型系统不支持高阶类型（Higher-Kinded Types）。这是刻意的设计决策，简化类型系统。

Gleam 有宏吗？

没有。Gleam 没有宏系统。use 是语法糖不是宏，它在编译时展开为回调函数。

Wisp vs Mist 何时选择？

Web 应用用 Wisp（路由、模板、表单、Cookie、会话），底层 HTTP/WebSocket/流式传输用 Mist。Wisp 建立在 Mist 之上，两者可配合使用。

Lustre vs React 有何不同？

Lustre 采用 MVU（Model-View-Update）架构，update 是纯函数；React 使用 Hooks，状态管理是命令式的。Lustre 无副作用，所有副作用通过 Effect 声明。

Gleam 能编译到 JavaScript 吗？

可以。使用 gleam run --target javascript 或 gleam build --target javascript。Gleam 支持编译到 Erlang（默认）和 JavaScript 两个目标。

如何处理 JSON？

使用 gleam/json 编码（Gleam 值 → JSON）和 gleam/dynamic/decode 解码（JSON → Gleam 值）。解码器提供类型安全的解析，错误时返回 DecodeError 列表。

练习 12.1 中间件 进阶

解释以下中间件的执行顺序：rescue_crashes → log_request → serve_static → handler。请求和响应分别经过哪些中间件？

洋葱模型：请求从外到内，响应从内到外。

请求方向：rescue_crashes → log_request → serve_static → handler
响应方向：handler → serve_static → log_request → rescue_crashes
即最外层中间件最先看到请求、最后看到响应。

练习 14.1 MVU 架构 进阶

实现一个 Lustre 计数器：Model 为 Int，Message 为 Increment / Decrement / Reset，view 显示当前值和三个按钮。

init 返回 0，update 用 case 匹配消息，view 用 on_click 绑定事件。

gleam
type Model = Int

type Message { Increment Decrement Reset }

fn init(_) -> Model { 0 }

fn update(model: Model, msg: Message) -> Model {
  case msg {
    Increment -> model + 1
    Decrement -> model - 1
    Reset -> 0
  }
}

fn view(model: Model) -> Element(Message) {
  div([], [
    p([], [text(int.to_string(model))]),
    button([on_click(Increment)], [text("+")]),
    button([on_click(Decrement)], [text("-")]),
    button([on_click(Reset)], [text("Reset")]),
  ])
}
练习 20.1 WebSocket 高级

编写一个 Mist WebSocket handler，对接收到的文本消息回显 "Echo: " <> msg，对 Binary 消息原样返回，连接关闭时打印日志。

用 mist.Text, mist.Binary, mist.Closed 匹配消息类型。

gleam
fn handle_ws(state, msg, conn) {
  case msg {
    mist.Text(text) -> {
      let assert Ok(_) = mist.send_text_frame(conn, "Echo: " <> text)
      mist.continue(state)
    }
    mist.Binary(data) -> {
      let assert Ok(_) = mist.send_binary_frame(conn, data)
      mist.continue(state)
    }
    mist.Closed -> {
      io.println("Connection closed")
      mist.stop()
    }
    _ -> mist.continue(state)
  }
}

练习 28.2 JSON 解码 进阶

fn user_decoder() -> decode.Decoder(User) {
  use name <- decode.field("name", decode.string)

}
练习 29.1 高级解码 高级

为枚举类型 pub type Color { Red Green Blue } 编写解码器，从字符串 "red"/"green"/"blue" 解码。

用 decode.then 先解码字符串，再用 case 匹配转换为枚举值。

gleam
fn color_decoder() -> decode.Decoder(Color) {
  use str <- decode.then(decode.string)
  case str {
    "red" -> decode.success(Red)
    "green" -> decode.success(Green)
    "blue" -> decode.success(Blue)
    _ -> decode.failure(Red, "Color")
  }
}
